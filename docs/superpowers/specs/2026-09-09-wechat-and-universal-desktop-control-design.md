# 微信与通用桌面操作设计规格

**日期：** 2026-09-09  
**状态：** 待用户审阅  
**范围：** 微信首期；Windows 文件管理器、浏览器、Office 的共享内核接入准备

## 目标

在现有 OpenWuKong 控制面之上，建立一套基于运行时能力发现的桌面操作内核。第一个可交付表面是个人微信 Windows 桌面端，目标是覆盖个人微信的全部基础桌面操作：应用和窗口生命周期、会话与联系人导航、消息读取与管理、文本和媒体收发、文件传输、搜索、通知、草稿、监控、设置和状态恢复。后续 Windows 文件管理器、浏览器、Office 通过同一套动作模型、能力图、风险门和验证器接入。

专用软件适配器可以提供更可靠的路径，但不能成为执行前提。没有适配器时，系统应根据当前窗口实际暴露的 UIA、Accessibility、DOM、Office 对象模型或视觉能力选择通用路径；无法定位或验证时安全阻断。

## 非目标

- 首期不承诺绕过微信自身权限、登录、风控、验证码或安全弹窗。
- 不自动执行删除、撤回、加好友、转账、红包、支付、批量群发等高风险动作；这些动作只产生计划并要求一次性、精确目标和动作确认。
- 不把 OpenClaw-Weixin 或其他 bot/API 渠道当作个人桌面微信控制；如果将来接入，它属于独立的 bot-channel 表面。
- 不在没有结果回读的情况下把键盘事件或桥接响应当作成功。
- 不在本规格中实现 Office 全部业务语义；本规格只冻结共享内核和首批 Office 接入边界。

## 用户可见能力边界

### 微信首期动作目录

“全部基础操作”在本规格中按操作类别定义。每个动作都必须注册到统一动作模型，并且必须有对应的能力探测、执行路径和结果验证；尚未支持的动作不能被静默忽略，而应返回明确的 `capability_missing` 或 `verification_failed`。

| 类别 | 基础操作 | 成功证据 |
|---|---|---|
| 应用与窗口 | 发现、启动、附着、最小化、恢复、最大化、关闭、重新绑定、登录状态检查 | 进程路径、PID、窗口句柄、标题、登录状态和状态变化一致 |
| 导航与搜索 | 搜索联系人、群、公众号或会话；打开、返回、置顶、取消置顶、标记未读、静音、归档 | 精确目标标识、导航后标题或会话标识回读 |
| 联系人与群 | 查看联系人信息、查看群信息、备注、标签、群公告和可见成员信息 | 目标身份、字段回读和权限状态一致 |
| 消息读取 | 读取文本、发送者、时间、系统消息、图片/文件/视频/语音等附件标记；搜索聊天记录 | 消息游标、来源会话、读取来源和置信度明确 |
| 消息编辑 | 草稿、复制、引用、回复、转发、收藏、翻译、标记、清理本地视图 | 目标消息标识和操作后状态回读 |
| 文本与表情 | 输入文本、发送文本、发送表情或可见表情包 | 目标会话匹配、发送动作完成、消息或标记回读 |
| 图片与媒体 | 选择、预览、发送图片、视频、语音或其他可识别媒体；下载或打开媒体 | 文件哈希或大小、缩略图/消息回读、下载路径状态 |
| 文件传输 | 选择文件、发送文件、接收文件、另存为、打开文件位置 | 授权路径校验、文件状态、会话消息或附件回读 |
| 接收与监控 | 监听新消息、未读数、桌面通知和指定会话变化；轮询、去重、暂停和恢复 | 时间窗口、会话游标、去重键和读取证据 |
| 设置与状态 | 读取和修改通知、快捷键、通用显示、聊天显示、下载目录等普通设置 | 修改前后字段回读，设置范围和恢复状态清晰 |
| 恢复与清理 | 恢复剪贴板、前台窗口、临时文件、监控游标和失败会话绑定 | 每个恢复步骤有结果，失败时转交用户接管 |

删除消息、撤回消息、加好友、邀请或移除群成员、批量转发、群发、红包、转账、支付、账号切换、登录授权和安全设置也纳入动作目录，但归入高风险副作用类别。它们可以被发现、规划和展示影响范围，执行必须有精确目标、一次性确认和动作后回读；不满足条件时阻断。

发送、文件上传、接收监控和普通设置修改属于可产生外部或本地副作用的动作。默认先生成计划和影响范围；只有用户确认且目标、会话、文件范围都稳定后才执行。

### 后续基础软件动作

共享内核为以下动作提供统一接口，具体语义在各软件接入时单独验证：

- 文件管理器：打开目录、导航、搜索、选择、复制、移动、重命名、创建目录、读取文件属性、删除到回收站；永久删除和覆盖写入需要额外确认。
- 浏览器：打开地址、读取页面、填写控件、提交、下载、读取下载结果；跨站提交、付款和敏感表单需要额外确认。
- Office：打开或创建文档、读取和写入结构化内容、保存、导出和关闭；优先使用 Office 对象模型或插件，UIA 和视觉路径作为受控回退。

## 架构

### 1. 统一动作模型

在 `ControlIntent` 的兼容字段之上增加面向桌面操作的规范化动作对象。每个动作包含：

- `action`: `inspect`、`search`、`open`、`read`、`draft`、`send`、`upload`、`download`、`save`、`monitor` 等稳定动词；
- `target`: 进程、窗口、会话、联系人或文件的结构化身份，不以模糊名称作为唯一依据；
- `parameters`: 动作参数，例如查询词、消息文本、文件路径、时间窗口、最大条数；
- `preconditions`: 执行前必须满足的状态，例如目标窗口、会话标题、文件哈希或登录状态；
- `effect_class`: 只读、草稿、本地写入、外部通信、删除或支付等副作用类别；
- `verification`: 期望的回读字段、标记、状态变化和允许的观察方式；
- `approval`: 所需的用户确认范围、确认 ID 和过期时间。

现有 `ControlIntent`、`ConnectorTarget` 和 `ConnectorActionResult` 保持向后兼容；新动作先转换为统一模型，再由控制 Fabric 生成计划。

### 2. 运行时能力图

新增能力发现层，为每个窗口或会话生成短生命周期 `SurfaceCapabilityProfile`。能力图只记录已经观察到的事实：

- 观察：窗口文本、控件树、截图、进程状态、DOM 或对象模型连接状态；
- 定位：automation ID、精确名称、控件类型、文本锚点、会话标识、视觉区域；
- 操作：`invoke`、`set_value`、`select`、`toggle`、键盘、鼠标、文件选择、DOM 或对象模型方法；
- 验证：事件、文本、截图、OCR、文件状态、页面状态或应用返回值；
- 约束：是否需要前台、是否会触碰剪贴板、是否允许后台执行、是否需要二次确认；
- 证据时间、进程 PID、窗口句柄、会话 ID 和能力来源。

能力图不从软件名称推断“必然可用”的动作。每次目标窗口、PID、登录状态或 UI 结构变化时重新探测或使旧能力失效。

### 3. 路径选择与回退

规划器对每个动作独立选择路径，而不是为整款软件永久绑定一条路径：

1. 已验证原生接口、扩展、DevTools 或对象模型；
2. UIA / Accessibility 语义控件；
3. 结构化 UIA 加前台输入；
4. 视觉定位加前台键鼠；
5. 只读探测或阻断。

每条路径返回能力级别、置信度、风险、前台要求、控制尝试计数和验证计划。失败后只允许回退到已经通过风险门的下一条路径；禁止在未重新确认目标的情况下盲目重试。

### 4. 微信适配层

微信实现拆为四个职责明确的组件：

- `WeChatSurfaceObserver`：发现个人微信窗口、会话区域、搜索框、消息列表、联系人或群面板、输入框、发送按钮、附件入口、通知和设置面板；只读。
- `WeChatTargetResolver`：将联系人、群、公众号、消息或文件名称转换为候选目标，要求精确匹配或用户从候选中确认；输出稳定目标身份。
- `WeChatActionExecutor`：按能力图执行生命周期、导航、读取、草稿、消息管理、文本或媒体发送、文件传输、监控、设置和恢复动作；优先语义控件，其次前台受控路径，native bridge 仅作为可验证增强。
- `WeChatResultVerifier`：通过 UIA 文本、截图、Python WinRT OCR、文件状态、窗口状态、消息游标和去重键验证结果，生成结构化报告。

现有 `wechat_uia_action.py`、`wechat_send_probe.py`、`wechat_native_bridge.py` 和 `foreground_takeover.py` 的安全检查复用到上述组件；现有 File Transfer Assistant 前台路径保留为一种受控执行器，不代表所有会话都已经具备同等能力。

### 5. 共享基础软件接入边界

- 文件管理器使用 Shell、UIA 和文件系统状态作为能力来源，先实现可逆文件操作和结果校验。
- 浏览器复用已有 Browser DevTools 连接器，同时将 DOM 能力投影为统一控件能力；无 DevTools 时才考虑 UIA 或视觉路径。
- Office 通过对象模型或插件提供结构化读写；每个 Office 应用单独定义对象模型健康检查和保存回读。
- 四类软件都必须通过同一套 `ControlFabric`、副作用门、前台接管和轨迹记录，不能绕过统一安全入口。

## 微信动作流程

### 发现和绑定

1. 枚举个人微信候选进程和顶层窗口，排除企业微信和 bot/API 表面。
2. 读取窗口句柄、PID、进程路径、标题、会话标识和初始截图或控件快照。
3. 生成 `SurfaceCapabilityProfile`，记录观察时间和能力来源。
4. 如果存在多个微信窗口或目标不明确，返回候选列表并停止执行。

### 搜索和打开会话

1. 使用语义搜索控件；若不存在，使用已批准的前台文本输入路径。
2. 等待结果稳定，收集名称、类型、头像或可用文本锚点。
3. 只有精确匹配或用户选择的候选才能打开。
4. 打开后重新读取会话标题和目标标识，防止搜索结果漂移。

### 读取和草稿

1. 读取消息列表的可见内容，规范化发送者、文本、时间和附件标记。
2. 对不可读取的内容保留来源和缺失字段，不把 OCR 猜测当作精确文本。
3. 草稿动作必须验证草稿内容已出现在输入控件中，且发送动作计数为零。

### 文本、图片和文件发送

1. 执行前验证目标会话、消息内容、文件路径、文件大小和副作用确认。
2. 优先调用语义 `set_value` 或 native endpoint；没有可靠后台能力时申请前台接管。
3. 前台路径在动作前保存剪贴板和前台窗口，在动作后执行消息回读、截图或 OCR，再恢复状态。
4. 文件发送使用工作区或用户明确授权的路径；拒绝路径越界、隐式目录递归和未知文件类型。
5. 失败或回读缺失时返回未确认状态，不自动重复发送，避免重复消息或重复文件。

### 接收监控

1. 监控必须绑定精确会话、PID、窗口句柄和时间窗口。
2. 以消息文本、发送者、时间和截图或元素标识组成去重键。
3. 轮询无变化时不产生用户通知；发现变化时先保存只读证据，再交给上层 Agent。
4. 窗口失效、登录状态变化或目标漂移时停止监控并要求重新绑定。

## 安全和状态规则

- 所有外部通信、文件上传、批量操作、删除、撤回、加好友和支付动作都经过副作用门。
- 前台接管请求必须绑定精确 PID、窗口句柄、窗口标题、动作和过期时间；批准内容与实际执行内容不一致时拒绝。
- 后台路径必须证明前台未被抢占，且键盘、鼠标、剪贴板和 UIA 前台变异计数满足路径约束。
- 目标解析默认精确匹配；多个候选、模糊匹配、不可读取控件和密码控件不自动写入。
- 所有临时截图、OCR、文件和轨迹产物使用明确目录并在动作结束后清理；清理失败必须进入报告。
- 轨迹记录动作计划、所选路径、证据摘要、尝试计数、验证结论和恢复结果，不记录密码或完整敏感消息内容；消息和文件内容只保存必要的哈希或截断预览。

## 错误处理

错误分为四类并保持可恢复语义：

1. `target_unresolved`：没有唯一目标；返回候选和需要用户选择的字段，不执行写操作。
2. `capability_missing`：当前表面不提供所需操作；尝试下一条安全路径，全部不可用时阻断。
3. `state_changed`：PID、窗口、会话、登录状态或 UI 结构变化；使能力图失效并重新观察，不直接重放旧动作。
4. `verification_failed`：动作可能已发生但结果不可确认；标记“未知”，禁止自动重复发送或上传，并保留回读证据供用户判断。

每个错误报告必须包含动作 ID、目标身份摘要、所选路径、失败阶段、是否有副作用尝试、恢复动作和下一步建议。

## 测试和验收

### 单元和契约测试

- 统一动作模型可序列化，旧 `ControlIntent` 调用保持兼容。
- 能力图只接受带 PID、窗口句柄、来源和时间的事实；过期或跨窗口能力不能执行。
- 路径选择在 native、UIA 语义、前台 UIA、视觉和阻断之间遵守优先级及风险门。
- 目标模糊、多个候选、密码控件、路径越界、前台批准不匹配和能力过期均零控制尝试。
- 验证失败不会自动重发；恢复失败会被记录。

### 微信离线回放

- 使用固定控件树、窗口状态和截图夹具覆盖应用或窗口生命周期、搜索和导航、联系人或群信息、消息读取与管理、草稿、文本或表情、图片或媒体、文件发送与接收、通知或设置、监控和恢复。
- 为每个动作类别记录支持的能力、首选路径、允许的回退路径、所需确认和结果验证器；没有能力的动作返回明确缺失原因。
- 分别验证语义控件、前台键鼠、OCR 和 native bridge 四种路径的报告字段与控制尝试计数。
- 用伪造的 PID、窗口标题、目标名称、消息游标和文件路径验证目标绑定、状态漂移、越界和重复操作阻断。
- 单独验证删除、撤回、加好友、群成员变更、批量发送、支付和安全设置等高风险动作在缺少确认或回读时不会产生控制尝试。

### 受控真实验证

- 先做只读探测和无发送 dry-run，再做单条、明确标记的 File Transfer Assistant 文本发送。
- 图片和文件只使用用户明确指定的临时文件，验证发送后回读和清理。
- 接收监控先验证无变化安静轮询，再使用单条 opt-in 标记消息验证去重和读取。
- 真实验证每次保存独立 JSON 报告，明确区分后台、前台、只读和未验证结果。

### 后续软件回归

- 文件管理器验证路径边界、可逆操作和文件系统回读。
- 浏览器验证 DOM 路径与 UIA 或视觉回退的等价动作结果。
- Office 验证对象模型保存、关闭后重新打开和内容回读。

验收标准不是“动作调用成功”，而是“目标正确、动作受控、结果可回读、状态已恢复或明确需要用户接管”。

## 实施顺序

操作目录一次性冻结为全部基础类别，下面的顺序只是降低实现风险的分批交付顺序，不改变首期范围。

1. 抽出统一桌面动作和能力图数据结构，接入现有 `ControlFabric`，保持现有连接器接口兼容。
2. 实现通用观察、目标解析、能力评分、路径规划、验证和轨迹记录的最小闭环。
3. 将微信现有前台发送、UIA 语义 dry-run、native bridge 合约接入统一执行器。
4. 先完成微信的搜索、读取、草稿、文本发送和回读，再加入图片或文件发送和接收监控。
5. 用同一内核接入 Windows 文件管理器、浏览器和 Office，优先可验证、可逆的基础动作。
6. 在真实验证证据充分后再调整 readiness matrix；没有证据的路径继续保持只读或阻断。

## 可观测性和交付物

- 每次动作输出结构化计划、执行报告和验证报告，包含 `selected_route`、`capability_profile`、`control_attempts`、`window_input_attempts`、`clipboard_write_attempts`、`verification` 和 `restore`。
- 新增的 schema 和报告版本必须可向后读取，旧报告不能被重新解释为更高能力等级。
- 代码、测试、离线夹具和最小使用说明一起交付；真实微信验证产物保留在项目运行日志中，不把个人聊天内容写入文档或测试夹具。
